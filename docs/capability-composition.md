# Compose Fresh Attempts Under a Capability Grant

The composition workspace asks whether generated records can reach the lab
receiver fully redacted, preserving their count and the receiver's retained
policy. A proposed graph may change compatible steps and parameters within a
reviewed installed method set. This is a new delegation, not a broader meaning
for an earlier exact-plan approval.

## Start From a Retained Control

Complete the original **Retain redaction and verify legitimate use**
[receiver control test](receiver-control-test.md) in the owned Linux lab. Keep
its policy retained and all receiver work settled. From that original test,
choose **Open composition workspace**. A linked retest or rolled-back control
cannot substitute for the original authority.

1. Enter the objective question and choose **Review finite delegation**.
2. Inspect the success condition, installed method versions and parameter
   domains, exact environment, data effects, cleanup reserve and cumulative limits.
   Adjust the requested limits and review again when needed.
3. Supply the reviewer identity, acknowledge that delegation, and choose
   **Issue capability grant**. The grant lasts 15 minutes from issue. Newly
   installed methods do not join it automatically.
4. Choose a configured model and request an initial graph, or **Review
   established graph** without making a model request. Graph inspection is
   read-only and does not replace the current Builder draft.
5. Inspect the steps, parameters, routes, rationale and supporting facts. Choose
   **Start fresh attempt within grant** to dispatch that candidate. The service
   checks current facts, compatibility, ownership and remaining authority again.

Model use needs separate purpose, data and usage authorization in Settings.
Select **Propose a bounded composition graph** for this operation. Saving a
provider or issuing an execution grant does not authorize a model request. There
is no provider substitution, deterministic fallback or automatic model retry.

## Revise From Actual Evidence

After an attempt is refused by the retained policy and its cleanup settles,
select its verified evidence in **Evidence-driven revision** and request a new
graph. Acceptance, unknown outcomes and incomplete cleanup are not revision
evidence for this objective. The model receives the
retained policy, classified receiver result and cleanup facts with their source
and validity. The service recompiles the proposed graph against the same grant;
the model cannot supply executor authority, invent a resource or broaden scope.

This is fresh-attempt composition. It does not mutate a running graph or resume
an interrupted effect. The prior attempt remains immutable. A successful objective
requires authenticated acceptance, the original nonzero record count, every record
redacted, unchanged receiver policy, and verified native and receiver cleanup.
Unknown observations and partial cleanup are not success.
Once the objective is established, new proposals and attempts stop, including
revisions selected from an older refusal. Inspection remains available.

## Budgets and Recovery

The first pack reuses fixture creation and transformation, file discovery or
metadata inspection, JSONL staging, authenticated loopback handoff and cleanup.
It rejects incompatible producers, conflicting fixed file writers, unsupported
parameters and methods without reviewed costs. The whole proposed graph is
reserved conservatively before effects, including branches not taken. Failed
attempts do not refund reservations; a new grant in the same lineage does not
reset spent budgets.

Workspace byte and file limits cover generated data artifacts, not native receipt
or control metadata. Retained-metadata bytes are an admission estimate, not an
enforced total-storage quota. The workspace displays these distinctions.

**Stop** pauses new business work and requests cancellation. **Revoke** closes
the grant permanently. Neither is proof that an in-flight effect has stopped.
Cleanup remains restricted to independently verified owned receipts, with its
original finite deadline; it does not extend business authority. Unknown effects
keep new work and control rollback unavailable until reconciled.

**Continue objective** preserves the original expiry and spent budgets. It does
not replay an interrupted attempt. Reloading reads saved jobs and pending request
identities; it sends no automatic effect retry. After a lost response, check saved
status before explicitly retrying the exact retained submission. Cancellation
and provider failure do not turn a late or stale proposal into an admissible run.

A saved delegation refusal issues no execution authority. **Review again**
preserves the question and requested limits for a new explicit review. An
unresolved submission is not a refusal: keep its identity until the saved result
establishes whether authority was issued.

## Scope of the Evidence

This first composition pack uses public generated JSONL in an authenticated,
owned Linux loopback lab. Its desired receiver policy is not persistent host
protection. Windows, macOS, effective cross-identity file access, AD and cloud
require their own methods and environment proof.

Compiler, persistence, protocol and provider-fixture tests establish software
behavior only. Installed native execution and a live model's evidence-based
decision are separate verification categories. No live-provider result or wider
program completion is claimed by this guide.
